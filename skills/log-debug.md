# 日志排查指南 —— 出问题时先看哪个文件

> 建立日期：2026-09-29
> 位置：`~/.termux-agent/`

---

## 一、日志清单（各管什么）

| 文件 | 记什么 | 什么时候看 |
|---|---|---|
| `turn.log` | **每轮结果**：正常完成 / 中断原因 / 耗时 / 轮次 | **第一个看**，判断"这轮到底怎么了" |
| `access.log` | 页面加载 / `/api/panel` / WS 连接 | 判断"前端到底有没有发出请求" |
| `supervisor.log` | 服务启动 / 健康检查失败 / 重启 / 回滚 | 服务反复重启、起不来 |
| `selfheal.log` | 自愈执行器的 tick 状态 | 跑飞、异常修复 |
| `evolve.log` | 自动进化执行记录 | 确认"是不是它改的代码" |
| `changelog.json` | 版本变更记录（自我更新/进化） | 查"什么时候改的、改了什么" |

---

## 二、排查顺序（照这个来）

### 1. 先看 turn.log 的结尾

```bash
tail -20 ~/.termux-agent/turn.log
```

**关键在第三列**：

- `正常完成` → 这轮没问题
- `中断-工具已发起但结果没收全` → **对话通道被掐断了**（最常见原因：自己 reload 了页面，见 ui-debug.md）
- `中断-回复为空(被重启/断连打断)` → 服务重启把正在生成的回复打断了

### 2. 判断前后端

```bash
tail -20 ~/.termux-agent/access.log
```

- **有 `/api/panel` 请求** → 后端没问题，去查**前端运行时**
- **没有** → 页面没更新，或者事件没绑上

### 3. 服务是不是在反复重启

```bash
tail -30 ~/.termux-agent/supervisor.log
```

看到连续的「判定服务异常 → 启动服务」= 服务反复挂。注意：**自我更新期间的健康检查失败是正常的**，1 秒内就"服务就绪"。

---

## 三、几个易错点

- **服务端 WS 是手写响应，不走 `log_message`** → `/ws` **不会**进 access.log，别以为没连上
- **access.log 超 512KB 自动清空** → 别指望它是长期记录
- **`_resume.md`** 是"上轮被中断"的临时提示文件，不是日志也不是清单

---

## 四、一行命令速查

```bash
cd ~/.termux-agent
tail -5 turn.log          # 最近 5 轮结果
tail -10 access.log       # 最近请求
tail -20 supervisor.log   # 服务启停
tail -20 changelog.json   # 最近改了什么
```
