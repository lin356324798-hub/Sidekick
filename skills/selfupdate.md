# 自我修改正规流程 —— 改 agent.py 自己

> 建立日期：2026-09-29
> 适用：修改 `~/.termux-agent/agent.py`（单文件，约 11000 行）

---

## 一、铁律

**改自己只有一条通道：`selfupdate` 工具。** 不要用 write_file / edit_file 直接改 agent.py —— 那会跳过备份和语法检查。

`selfupdate` 替你做的事：

1. 自动备份当前版本到 `versions/`
2. 检查新代码的 **Python 语法**（失败立即还原）
3. 成功后服务自动重启加载新代码
4. 若新代码起不来，**看门狗回滚**到上一个可用版本

**注意：它只查 Python 语法，不查 HTML/CSS/JS。** 内嵌的 `WEB_HTML` 里写错 JS 它不会拦你 —— 所以前端改动要另外验证（见下）。

---

## 二、标准动作

### 1. 先读，别猜

```
read_file  agent.py  offset=<大概位置>  limit=60
grep       "关键词"    # 定位准行号
```

**行号会漂移** —— 别的进程（自动进化/自愈）也会改这个文件。**每次改之前重新 grep 一次**，别信上一轮记的行号。

### 2. 写最小 patch

`patch_old` 必须与源码**逐字符一致**（含缩进），且**在全文唯一**。

- 报"没找到" → 大概率是内容变了或空白字符差异，重新读一遍再写
- 报"不唯一" → 把前后几行一起写进 `patch_old` 缩小范围

### 3. 一次一处

`selfupdate` 只接受一组 `patch_old` / `patch_new`。
**多处不相邻的改动 → 要么合并成一段连续的、要么分批做**（代价是多次重启）。

### 4. 调用后本回合立刻结束

服务要重启，**不要再调任何工具**，直接向用户说明改了什么。验证放到下一轮。

---

## 三、坑

| 坑 | 说明 |
|---|---|
| 大范围重写 | 文件 1 万行，整份 `new_code` 极易出错，**永远优先用 patch** |
| 频繁 selfupdate | 每次都会重启服务 + 打断对话，**攒一攒再改** |
| 只验证 Python 语法 | 内嵌 JS 的错它查不出，**前端改动要跑 CDP 实测** |
| 改完就 reload 页面 | **绝对禁止**：用户正用这个页面跟你对话，刷新会掐断 WebSocket（详见 `ui-debug.md`） |

---

## 四、前端改动的验证姿势

改完 `WEB_HTML` 后（等服务重启完）：

```bash
cd ~/.termux-agent
timeout 25 python3 cdp.py "JS表达式" -p 8765     # 直接读页面真实计算样式
```

**不要**用 `location.reload()` —— 让**用户自己刷新**，或者直接读计算样式（CSS 变量、`getComputedStyle` 都能读到）。

---

## 五、回滚

- **看门狗自动回滚**：新代码起不来时
- **手动**：`versions/` 目录里有历史版本，`last-good.py` 是最近可用的
- **服务状态**：`cat supervisor.log` 看启动/回滚记录
